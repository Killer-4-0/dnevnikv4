# Мой дневник здоровья (v3)

Дневник питания с КБЖУ, тренировками, планами, графиками и прогнозом веса. Работает офлайн (PWA), устанавливается на телефон. Данные хранятся на устройстве (localStorage), синхронизация между устройствами — опционально через Firebase.

## Что нового в этой версии

- **Распознавание КБЖУ по фото через ИИ (Munito)** — ключ уже встроен, фотографируешь тарелку → получаешь блюда, вес и КБЖУ (модель GLM 5.3 Flash, проверена на реальных фото).
- Убрана зависимость от Gemini API (отдельный ключ Google больше не нужен).
- Поддержка прокси для обхода CORS (GitHub Pages).
- Вкладка «API» для проверки ключа и чата с моделями.

## 1. Открыть с телефона через GitHub Pages

Приложение полностью статическое — GitHub Pages подходит идеально.

1. Залейте эту папку в репозиторий GitHub (например, `dnevnik-v3`):
   ```
   git init
   git add .
   git commit -m "v3"
   git remote add origin https://github.com/ВАШ_ЛОГИН/dnevnik-v3.git
   git push -u origin main
   ```
2. GitHub → ваш репозиторий → **Settings** → **Pages** → Source: **Deploy from a branch** → ветка `main`, папка `/ (root)` → **Save**.
3. Через минуту приложение будет на `https://ВАШ_ЛОГИН.github.io/dnevnik-v3/`.
4. Откройте эту ссылку на телефоне → меню Chrome `⋮` → **«Установить приложение» / «Добавить на главный экран»** — появится как обычное приложение, работает и офлайн.

## 2. Прокси для распознавания фото (нужен на GitHub Pages)

Браузер блокирует запросы с https-сайта к чужому API без заголовка CORS (проверено: Munito его не отдаёт). Без прокси «Фото блюда» и вкладка «API» на GitHub Pages не работают.

**Самый простой способ — Cloudflare Pages вместо (или вместе с) GitHub Pages.** Не надо ничего вставлять в редактор: прокси лежит готовым файлом в репозитории.

1. `dash.cloudflare.com` → **Workers & Pages** → **Create application** → **Import a Git repository** → подключи свой GitHub-репозиторий.
2. Build settings: **Framework preset: None**, build command пусто, output directory не меняй → **Save and Deploy**.
3. Через пару минут сайт на `https://название.pages.dev` — открой с телефона.
4. Файл `functions/api/chat.js` уже в репозитории: Pages сам сделает из него прокси.
5. В приложении: **Настройки → ИИ → Прокси** → впиши `https://название.pages.dev` → **Сохранить**. Всё, фото работает.

**Альтернатива — Cloudflare Worker** (когда дашборд показывает кнопку «Create application»: выбери шаблон Hello World → Deploy → Edit code → вставь содержимое `worker.js` → Deploy → впиши адрес `https://воркер.аккаунт.workers.dev` в «Прокси»).

Workers AI от Cloudflare для этой задачи **не подойдут**: это другие ИИ-модели (не прокси), их API тоже не отдаёт CORS-заголовки (проверено), а токен аккаунта нельзя встраивать в публичный сайт — это опасно.

Лимиты: Pages/Workers бесплатно — 100 000 запросов в день, хватит с запасом.

## 3. Без прокси: запуск с компьютера (домашняя сеть)

`server.js` отдаёт и само приложение, и прокси — ничего настраивать не нужно:

```
node server.js
```

Откройте `http://localhost:8787` на компьютере, а на телефоне (в той же Wi-Fi сети) — `http://IP-КОМПЬЮТЕРА:8787` (узнать IP: `ipconfig` → IPv4-адрес). Всё работает, включая фото.

## 4. Синхронизация между устройствами (опционально)

Настройки → «Синхронизация (вход по почте)» → инструкция внутри. Нужен бесплатный проект Firebase (5 минут). Без этого данные живут только на одном устройстве.

## Настройки ИИ

- **Ключ** — встроен (`js/config.js`), можно вписать свой.
- **Модель** — `zai-org/glm-5.3-flash` (лучшая для фото), `qwen/qwen3.8-27b`, `deepseek-ai/deepseek-v4.1-flash-1017` (все проверины: видят фото и отвечают JSON). `deepseek-ai/deepseek-v4-flash` фото не видит.
- ⚠️ **Внимание**: на GitHub Pages ключ из `js/config.js` виден всем посетителям сайта. Для личного пользования это нормально; не публикуйте приложение с ключом публично, если ключ используется где-то ещё, и периодически меняйте ключ.

## Экспорт/бэкап

Настройки → «Данные» → «Экспорт» — скачивается JSON со всеми записями (ключи в файл не попадают).
